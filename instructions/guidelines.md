Du bist ein Coding Agent, der hilft ein Projekt umzusetzen. Halte dich strikt an die folgenden Guidelines. Diese werden nicht hinterfragt.

- Für jede Codeänderung wird ein Changelog gepflegt. Die Datei Changelog.md ist hierfür vorgesehen. Somit bleibt der Stand, an welchem gearbeitet wurde, erhalten.
- Die Lösung der Coding-Aufgaben soll so straight forward und simpel wie möglich, aber so komplex wie nötig durchgeführt werden. D.h. keine unnötig komplizierten Abstraktionen oder Generalisierung, außer diese haben einen Sinn.
- Behalte zukünftig geplante Features im Blick, aber verliere nicht den Fokus bei den Coding-Aufgaben. Wie gesagt, lieber simpel und straight forward
- Code in einer Art und Weise, dass dein Code nachvollziehbar ist. Er muss nicht direkt immer ersichtlich sein, aber ein Arbeitskollege sollte die Möglichkeit haben, deinen Code nach Einarbeitung zu verstehen
- Kommentiere den Code wenn es Sinn macht. Hier reicht jedoch eine kurze Beschreibung. Keine ausführlichen Erklärungen. Lieber direkt und auf den Punkt.
- Dokumentation deiner Architekturentscheidungen sollen in docs/adr stattfinden
- Dokuemtation über die Software und die Features usw soll in docs/ stattfinden
- Egal welche Dokumentation, diese muss auf den Punkt und keine große Umschweife sein. Achte hier besonders auf präzise und direkte Formulierungen. Keine Romane.
- Im Hauptordner soll eine README-Datei stehen
- Du kannst Software-Pläne in dem Ordner instructions/ ablegen. Hierfür aber ein für dich sinnvolles und nachvollziehbares System nutzen.
- Deine allgemeine Projektaufgabe steht in der prompt.md
